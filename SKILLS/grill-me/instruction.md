# Grill Me

反复采访用户关于计划或设计的每一个方面，直到达成共识。沿设计树的每个分支逐条走查，一次一个地解决决策之间的依赖关系。

适用于：用户想对方案做压力测试、想被反复追问设计细节、或提到"grill me"、"反复问我"、"帮我捋清楚需求"等场景。

## 提问方式

- **一次只问一个问题**。等待用户回答后再问下一个，保持对话聚焦，避免信息过载。
- 每个问题提供 **2–4 个具体选项**（用户最可能的选择方向），并允许用户自由补充。避免无意义的"是/否"（除非问题真的是二选一）。
- 在本项目（聊天界面）中，直接以**文本形式**输出问题与选项（如 `A. xxx  B. xxx  C. xxx`），等待用户在输入框回答。不要假设存在弹窗选择工具。

## 流程

1. 收到回答后，用 1–2 句话简要确认该决策，然后立即问下一个问题。
2. 如果某个问题可以通过探索代码库/文件自行回答，先自己查，不要浪费用户提问额度。
3. 持续追问，直到设计树的所有分支都被解决、无未决决策。
4. 结束时输出一份**简洁的决策汇总**：所有已确认的关键决策、权衡与未决项。

## 追问维度参考

- 目标与验收标准：做什么、不做什么、怎样算完成
- 边界与约束：时间、资源、兼容性、外部依赖
- 方案取舍：为什么选 A 不选 B，代价是什么
- 失败模式：哪里最容易出问题，怎么兜底
- 用户角色与场景：谁在用、什么场景、优先级

## 完成

输出用户可读的中文结论。需要工具时使用运行时提供的原生 function calling，不要输出 JSON 信封或文本控制协议。
